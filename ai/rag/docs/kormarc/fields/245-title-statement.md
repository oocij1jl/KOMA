## Purpose

245 필드는 자료의 표제와 책임표시사항을 기술하는 필수 필드이다. 반복할 수 없다.

이 서비스에서 245는 **추론 필드가 아니다.** 국중도 `TITLE`/`AUTHOR`/`VOL`(정보나루 `bookname`/`authors`/`vol`)에서 온 `biblio.title`, `biblio.author`, `biblio.volume`을 코드가 규칙으로 식별기호에 배치한다. 값을 새로 만들거나 바꾸지 않는다.

## Official KORMARC Summary

- 반복불가 필드이며 필수 필드이다.
- 제1지시기호는 표제 부출 여부를 나타낸다(`0` 부출하지 않음, `1` 부출함, `2` 관제를 포함해서 부출함).
- 제2지시기호는 표제 배열을 나타낸다(`0` 그대로 배열, `1` 원괄호를 제외하고 배열).
- 책임표시는 첫 번째가 `d`, 두 번째 이하가 `e`이다. **`c`는 245에 정의된 식별기호가 아니다.**
- `h`는 자료유형표시이며 각괄호로 묶어 본표제 다음에 기술한다. 저자명을 넣는 자리가 아니다.
- `b`는 표제관련정보(부제)이고, `x`는 대등표제, `n`은 권차/편차, `p`는 권제/편제이다.
- 저작의 역할이 같은 저자 사이는 반점(`,`), 역할이 다르면 쌍반점(`;`)으로 구분해 `e`를 기술한다.
- 245 필드는 약자·두문자·구두점으로 끝나는 데이터가 아니면 필드 끝에 구두점을 기술하지 않는다.
- 제2지시기호 `1`은 본표제 첫머리에 배열에서 제외할 관제·관사가 있고 그것을 원괄호로 묶은 경우에 적용한다.

MARC21의 “비배열 문자 수”를 제2지시기호에 넣는 방식은 KORMARC 규칙이 아니므로 사용하지 않는다.

## Input Mapping

245는 evidence(키워드·책소개·함께 대출된 도서)를 근거로 쓰지 않는다. 아래 biblio 값만 사용한다.

| biblio 키 | API 원본 | 목표 식별기호 |
|---|---|---|
| `title` | 국중도 `TITLE` / 정보나루 `bookname` | `a`, 필요 시 `b`, `x` |
| `volume` | 국중도 `VOL` / 정보나루 `vol` | `n` |
| `author` | 국중도 `AUTHOR` / 정보나루 `authors` | `d`, 필요 시 `e` |

`evidence.keywords`, `description`, `co_loan_books`는 245 생성에 사용하지 않는다. 주제어가 표제에 섞이는 오염을 막기 위한 규칙이다.

| `indicator2` | 기본 `0`. 본표제가 원괄호 관제로 시작하면 `1` | 공식 규칙의 표제 배열 정의 |

## Service Generation Rule

1. `biblio.title`이 비어 있으면 245를 생성하지 않고 `skipped_fields`에 남긴다. 표제를 추론해서 만들지 않는다.
2. 본표제는 `biblio.title`을 그대로 쓴다. 표기·띄어쓰기·문장부호를 교정하지 않는다.
3. 대등표제: 표제에 ` = `가 있으면 앞을 `a`, 뒤를 `x`로 나눈다. 구분자가 없으면 `x`를 만들지 않는다.
4. 부제: 표제에 `:` 구분자가 있고 앞뒤가 모두 비어 있지 않을 때만 첫 번째 `:`를 기준으로 `a`/`b`로 나눈다. 구분자가 없으면 나누지 않고 전체를 `a`에 둔다. **근거 없는 임의 분리 금지.**
5. `biblio.volume`이 있으면 `n`에 기술한다.
6. 책임표시는 `biblio.author` 문자열을 다음 순서로 나눈다.
   1. `;`가 있으면 그 기준으로 나눈다.
   2. `;`가 없으면 역할어(`지음`, `글`, `그림`, `글그림`, `옮김`, `엮음`, `편역`, `편저`, `번역`, `감수`, `사진`, `저`, `역`, `편`) 뒤에서 나눈다. 단, 역할어 앞에 이름 성분이 하나도 없으면(예: `지은이 박아림`, `글 유상아`) 나누지 않는다.
   3. 나뉜 첫 번째가 `d`, 나머지가 `e`이다.
7. 역할어도 `;`도 없으면 전체를 `d` 하나로 둔다. 공백만 보고 사람 이름을 임의로 쪼개지 않는다.
8. `value`에는 ISBD 구두점(` :`, ` /`, ` ;`, `,`)을 넣지 않는다. 구두점은 출력 단계 책임이다.
9. 245는 biblio 전사 결과이므로 `source="api"`, `generated_by="rule"`로 기록한다. `evidence` 객체는 만들지 않는다.
10. 표제만 있고 책임표시가 없으면 `d`/`e` 없이 생성하고 검수 대상으로 둔다. 저자를 추론해 채우지 않는다.
11. 부제 분리·책임표시 분해가 일어났거나 `author`가 비면 `review_required=true`로 둔다.

## Skip Rule

| Condition | Reason |
|---|---|
| `biblio.title`이 빈 문자열 | `표제 근거 없음: 245 생성 불가` |

`biblio.author`가 비어 있어도 245 자체는 생성한다. 표제는 필수이고 책임표시는 자료에 없을 수 있다.

## Forbidden

- 책임표시를 `c`에 넣지 않는다. KORMARC 245에 `c`는 없다.
- 저자명·부제를 `h`에 넣지 않는다. `h`는 자료유형표시다.
- 표제에 구분자가 없는데 부제를 만들어 내지 않는다.
- evidence(키워드·책소개)에서 표제나 부제를 가져오지 않는다.
- 제1지시기호에 `1`을 넣지 않는다. 이 서비스는 1XX를 만들지 않는다.
- 제2지시기호에 비배열 문자 수를 넣지 않는다. MARC21 방식이다.
- 표제 오탈자를 임의로 고치지 않는다. 검수 대상으로 남긴다.

## Risk and Validation

- 245는 필수·반복불가이므로 레코드당 1개만 있어야 한다.
- `a`는 반드시 있어야 한다.
- 허용 식별기호는 `a b d e f g h k n p s x 6 8`이다. 그 외 코드(특히 `c`)는 오류다.
- `value`에 ISBD 구두점이나 `▼`가 있으면 경고한다.
- 부제 분리와 책임표시 분해는 사서 검수 대상이다.
- API 표제와 실물 표제가 다를 수 있다. 값 불일치는 입력 데이터 문제로 분류하고 임의 수정하지 않는다.
