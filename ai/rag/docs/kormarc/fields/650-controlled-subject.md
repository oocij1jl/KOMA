## Purpose

650 필드는 통제된 주제명표목표나 시소러스에 근거한 일반주제명을 기술하는 주제 접근 필드이다.

이 서비스에서는 650을 보조 필드로만 사용한다. 정보나루 `keywordList`의 자유 키워드는 기본적으로 653 비통제 색인어로 처리하며, 표목표 출처와 주제명 대조 근거가 없는 자유 키워드를 650으로 임의 승격하지 않는다.

## Official KORMARC Summary

- 반복 가능 필드이다.
- 해당 시 필수 성격의 필드이다.
- 제1지시기호는 주제의 수준을 나타낸다.
- 제2지시기호는 주제명표목표 또는 시소러스를 나타낸다.
- 650은 제2지시기호나 `2` 식별기호에 명시된 리스트와 전거파일에 근거하여 주제명표목을 부여할 때 사용한다.
- 주요 식별기호는 `a`이며, 주제명 또는 주제명 표목으로 사용된 지명을 기술한다.
- 주제세목은 `v`, `x`, `y`, `z` 식별기호로 구분한다.

## Mandatory Source Rule

650은 통제 주제명 필드이므로 **제2지시기호 출처를 확정할 수 없으면 생성하지 않는다.**

정보나루 키워드는 비통제 자유어이므로 그 자체만으로 650 생성 근거가 되지 않는다. 현재 `(A') evidence` 스키마의 `keywords`, `description`, `co_loan_books`는 650 후보 판단을 보조할 수는 있지만, 주제명표목표 대조 결과나 제2지시기호 출처를 확정하는 evidence가 아니다.

현재 스키마 기준으로는 다음 조건이 모두 충족될 때만 650 생성을 고려한다.

1. 주제명표목표 또는 시소러스 출처가 명확하다.
2. 제2지시기호 값을 확정할 수 있다.
3. 제2지시기호가 `7`인 경우 `2` 식별기호에 넣을 정보원 부호를 확정할 수 있다.
4. 실제 주제명표목 대조 결과가 별도 근거로 남아 있다.

위 조건을 충족하지 못하면 650은 반드시 `skipped_fields`에 남긴다. 현행 evidence 스키마만 입력으로 받은 LLM은 650을 생성하지 않는 것이 기본 동작이다.

## Service Generation Rule

1. 650은 기본 생성 대상이 아니라 보조 제안 대상이다.
2. 정보나루 키워드만 있는 경우 650을 생성하지 않고 653으로 처리한다.
3. 통제 주제명표목표 대조 결과가 있을 때만 650 생성을 고려한다.
4. 제2지시기호 출처를 확정할 수 없으면 650을 생성하지 않는다.
5. 제2지시기호를 LLM이 추측해서 채우지 않는다.
6. `indicator2="7"`을 사용할 때는 `2` 식별기호의 정보원 부호가 반드시 확정되어야 한다.
7. 생성 시 `source="ai_inference"`, `review_required=true`, `confidence="low"` 또는 `"medium"`을 부여한다.
8. 생성 시 사용한 표목표 출처와 대조 근거를 출력 필드의 `evidence.reasoning`에 남긴다.

## Forbidden

- 정보나루 자유 키워드를 650으로 임의 승격하지 않는다.
- 제2지시기호 출처를 모르는 상태에서 650을 생성하지 않는다.
- 제2지시기호 값을 LLM이 추측하지 않는다.
- NLSH, LCSH, MeSH 등 표목표 대조 근거 없이 `indicator2`를 채우지 않는다.
- `indicator2="7"`일 때 `2` 식별기호 없이 생성하지 않는다.
- 통제 주제명인지 확인되지 않은 키워드를 `a`에 넣지 않는다.

## JSON Output Rule

650은 생성 조건을 만족하는 경우에만 아래 형태로 출력한다. 현재 evidence 스키마는 정보나루 키워드, 책소개, 함께 대출된 도서만 제공한다. 이 정보만으로는 650의 제2지시기호 출처를 확정할 수 없다. 따라서 별도의 주제명표목표 대조 결과가 없는 한 650 필드는 생성하지 않고 653으로 대체한다.

```json
{
  "tag": "650",
  "indicator1": " ",
  "indicator2": "8",
  "subfields": [
    { "code": "a", "value": "한국 영화" }
  ],
  "source": "ai_inference",
  "review_required": true,
  "confidence": "medium",
  "note": "국립중앙도서관 주제명표목표 대조 근거 필요. 사서 검수 필수",
  "evidence": {
    "from": ["keywords", "description"],
    "reasoning": "NLSH 대조 근거와 제2지시기호 8의 출처 확정 근거가 별도로 확인된 경우에만 650으로 제안"
  }
}
```

`indicator2` 출처를 확정할 수 없는 경우 위 JSON을 생성하지 않는다.

## Skip Rule

650을 생성하지 말고 `skipped_fields`에 남긴다.

| Condition | Reason |
|---|---|
| 정보나루 키워드만 있고 표목표 대조 근거가 없음 | `통제 주제명은 표목표 대조 필요: 653으로 대체` |
| 현행 evidence가 `keywords`, `description`, `co_loan_books`뿐임 | `650 출처 확정 evidence 없음: 653으로 대체` |
| 제2지시기호 출처를 확정할 수 없음 | `650 제2지시기호 출처 미확정: 생성 금지` |
| `indicator2="7"` 후보이나 `2` 정보원 부호가 없음 | `650 정보원 부호 미확정: 생성 금지` |
| 주제명이 통제어인지 확인되지 않음 | `통제 주제명 확인 불가: 653으로 대체` |

## Risk and Validation

- 650은 통제 주제명이므로 653보다 위험도가 높다.
- `review_required`는 항상 `true`로 둔다.
- `source="ai_inference"`이면 `evidence` 객체가 반드시 있어야 한다.
- `indicator2`는 필수 검증 대상이다.
- `indicator2="7"`이면 `2` 식별기호가 반드시 있어야 한다.
- `value`에는 출력용 두 줄 붙임표(`--`)나 ISBD 구두점을 넣지 않는다.
- `v`, `x`, `y`, `z` 주제세목 앞의 출력용 `--`는 시스템 표시 형식이며 MARC 값에 입력하지 않는다.
- 근거가 불충분하면 생성하지 않고 653으로 대체한다.
